## 架构边界

离线管线：ISO → DATA.DAT / EBOOT.BIN → 原版脚本指令与资源 → Unicode JSON / PNG / AAC。

运行时：TypeScript 脚本状态机 → React DOM 文本与输入 → CSS 布局、HTMLAudioElement 音频、IndexedDB 存档。

没有执行 MIPS 指令，没有加载 PSP 字库，没有在浏览器里做 Shift-JIS 或汉化码表解码。保留的是脚本控制流与资源引用关系。没有试图重建原作者的 C/C++ 源码，反汇编用于确认行为，再以 TypeScript 表达已验证的语义。

## 脚本结构与控制流证据

- `0x08852084` 加载 story.dat，`0x0885208c` 调用 `0x08823b10` 注册。
- `0x08823bb0` 调度器从指令 +2 读取 uint16 opcode，以 opcode / 100 查类别表。
- 类别表 `0x08882208`，20 个 `(类别, 子表地址)`；子表为 `(opcode, handler)`，函数地址 0 为终止。
- 指令以 FF 开头，第二字节是**实际字节长度**；不能统一按 4 字节对齐。零填充另行跳过。
- story.dat 首部记录索引边界 0x4248、记录数 2120，随后 `(id, offset)`。正常序章的记录 1、2、3 起点分别为 0xd5e4、0xdc30、0xe7b4；备用记录 4 从 0xf370 开始。

| 指令 | 已核对行为 / 地址 | Web 行为 |
| --- | --- | --- |
| 1 / 2 | 开始 / 结束 | 初始化段位置 / 结束序章 |
| 3 / 4 | 对话块边界，0x08819ee4、0x0881a378 | 聚合一段正文后等待继续 |
| 101 | 跳转，0x0881a444 → 0x08826488 | 切换脚本与指令指针 |
| 106 / 107 | 条件块，0x0881a694 | 按标志匹配；失败跳过嵌套块 |
| 801 | 标志写入，0x0881e8d0 | 先置位，再清除 |
| 213 | 名字字段，0x0881c0dc → 0x08818f9c | 插入原生 Unicode 名字 |
| 1001 | 姓名输入，0x08820034 | HTML 表单，字段 0 / 1，最大 5 字符 |
| 401 / 403 | 图层资源与透明度 | 已转换背景、可见图层选择 |
| 902 / 904 / 905 / 906 | 音乐资源、播放、音量、停止 | 浏览器音频；淡出简化为状态变化 |
| 2013 | 术语解锁，0x08821b9c | 解锁名称，不把载荷当正文 |

106 和 801 参数首 uint16：低 8 位为需开启/置位的数量，高 8 位为需关闭/清除的数量；后续是标志 ID。初始化 `0x08818c38` 清零状态。原版记录 2 在分支前主动清除 2490；默认走 3。测试在分支检查位置注入 2490，验证备用 4 的可执行性，产品不额外显示虚构选择。

结束前写入 3150，正常路线解锁术语 1、2、3、4、108。共 44 段正文、两次姓名输入和一个结束停顿，即 47 个可存档位置。

## 汉化文本解码

`0x08825d84` 文本路径在 `0x08825da4 / 0x08825dac` 对字节 XOR FF；0x81–0x9f / 0xe0–0xfc 是双字节首字节。但是直接按 CP932 解码无法还原汉化内容，例如某些编码显示为“丑”，实际字形却是“你”。因此不能用通用日文解码器作为最终正文。

字形查找 `0x0883e498`：

- 单字节索引 `lead - 0x20`。
- 双字节索引 `(lead - (lead < 0xa0 ? 0x81 : 0xc1)) * 192 + trail - 0x40 + 0x5f`。
- FontA.fnt 在 `2 + index * 2` 存放 uint16 字形编号。
- `0x0883e530` 选择 atlas：小于 889f 为 0，889f 至 9872 为 1，9873 起为 2。
- `.ftx` 开头 uint32 是字形宽度 32；调色板字节数 `u16@10 * u16@12 * 4`，像素从 `16 + paletteBytes` 开始。
- 32×32、4 bpp，低半字节在前，每字形 512 字节。渲染路径见 `0x0883dafc..0x0883dbec`。

将序章 1–4 使用的 484 个字符渲染成校对表，按实际字形手工核对后写入 `prologue-glyph-map.json`。编译器遇到未核对字符会失败，不通过猜词或替代字符继续。此映射只覆盖首版范围，不代表已解决全游戏的全部字符。人工字形校对仍可能需要后续逐句复核。

网页拿到的是普通 Unicode。三个原版破折号片段合并为两个破折号；原版按钮图标 217 适配为“菜单”。保留正文分行，但不依赖 PSP 字宽。

## 背景和音乐

命名 NISPACK 不包含全部资源。全局资源表在 `0x0887A9CC`，每条 `(DATA.DAT offset, size)` 共 8 字节；1537 对应 NISPACK。纹理映射 `0x0887D9DC` 共 396 条 `(textureId, resourceIndex)`，调用路径 `0x08852ee4 → 0x08852d08`。

| 纹理 | 资源编号 | DATA.DAT 偏移 | 尺寸 |
| --- | --- | --- | --- |
| 196 | 84 | 0x029c8000 | 480×272 |
| 515 | 121 | 0x02c50000 | 480×272 |

资源头 16 字节，PSP DXT1 每块 8 字节顺序是 **u32 索引在前、两个 RGB565 端点在后**。不能照搬标准 DXT1 字节顺序。已离线输出 PNG，并检查原图内容。当前解码器用于这些不透明背景，未泛化透明纹理。

音乐加载入口 `0x08865080`；表 `0x0887FA90`，每条 20 字节，+4 是 int16 资源编号。BGM 6 / 8 / 9 分别为资源 1038 / 1040 / 1041，RIFF ATRAC 经 ffmpeg 转 AAC 128kbps M4A。

## 存档与验证

存档保存脚本 ID、下一指令指针、名字、标志、图层、音乐、正文记录、术语等。版本指纹由 story.dat、字形映射及转换版本常量组成。加载时核对版本、位置、字段、资源和等待指令；写入串行化避免自动保存乱序。

Node 测试执行正常全程、备用条件路径、每个停顿点恢复、嵌套条件、未知操作、非法目标和循环保护。Python 测试覆盖容器边界、文本转换、精确指令长度和 PSP DXT1 字节布局。真实浏览器验证情况以实际交付说明为准；这些单元测试本身不等价于原 PSP 全程对照验证。
