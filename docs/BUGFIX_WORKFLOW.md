# 手动测试问题的复现与修复流程

适用阶段：全部章节已经接入、简中译稿已经补齐后的持续修复。先读 PROJECT_STATUS；技术排错顺序见 DEBUGGING，翻译修订仍走 TRANSLATION_WORKFLOW。

## 玩家只需提供这些信息

不要求玩家提供 script、pc、opcode 或 JSON。优先记录：

1. 哪一章，附近一两句原样对白（可直接复制）。
2. 看到了什么，本来希望怎样；最好附一张含场景和正文的截图。
3. 刚才做了什么：点继续、选哪个选项、读档、刷新、切语言等。
4. 手机/电脑、浏览器、横竖屏；如果调过字号或浏览器缩放，一起说明。
5. 每次都出现还是偶发；涉及动画时，说明“刚进入”还是“等待几秒后”。

有条件就先手动保存到**空槽**，保留问题发生前的位置。不要要求玩家覆盖珍贵存档、清网站数据、重开整章或刷新一个尚未保留的现场。单个问题一条记录；信息不足先登记“待复现”，不是立即归类为原版行为。

## 从中文原句定位

```sh
npm run qa:bug -- locate --text '你明天再来' --entry 70001
# 不知道章节时省略 entry；默认 zh-Hans，最多展示 10 条
npm run qa:bug -- locate --text '警署' --limit 20
```

搜索当前译文与源文，忽略空白和全半角差异（仅用于搜索，不改译文）。列出 key、真实章节入口、脚本、页起点、route/trial/step、源文/译文有限摘录。相同台词可能出现在不同路线，**不能默选第一项**；用截图、前后对白与最近选择进一步缩小。共享静态词条会列出多个章节范围，不代表在所有路线都已出现。

`pageStartPc` 是正文块开始位置，**不是**引擎停顿后的 `state.pc`。不要据此构造存档。截图中的自定义姓名可能与语料默认名不同，定位时优先选不含姓名的句子。图像内文字、按钮 UI、用户输入不一定在剧情语料内；零匹配时读对应组件或 evidenceText，不编造位置。

语料缺失或指纹过期会拒绝查询，按错误提示重建；不要为绕过检查只改 manifest。只有翻译发生变化、game.json 未变时无需重新提取源语料。

## 建立问题证据包

```sh
npm run qa:bug -- report --id yuka-wall-text --text '你明天再来' --entry 70001
```

生成 `output/qa/bug-yuka-wall-text/`：

- `REPORT.md`：玩家观察、候选位置、根因、修复及验收待填写项。
- `matches.json`：有上限的匹配清单；total/truncated 明确是否尚有其他候选。
- `report.json`：游戏、源文件、语料、语言目录 SHA；Git HEAD 与 dirty 状态；生成时间。

证据包拒绝覆盖。续办修改原 REPORT.md；若需记录新基线，使用新 ID，并写明关联关系。output 是可再生工作区，**不是长期 bug 台账**。确认问题后将精简记录落到 `docs/bugs/`，真正需要回归的路线放 tests/fixtures；不将大检查点包全部提交。

如果已有对应 QA 检查点，可一起保留：

```sh
# 若没有这个检查包，先按 TOOLING 生成 remaining-zh-hans
npm run qa:bug -- report --id yuka-wall-repro --text '你明天再来' --entry 70001 --bundle remaining-zh-hans --scene media-3005
# 独立测试 origin 中打开：
# /tests/qa.html?bundle=bug-yuka-wall-repro&scene=repro&lang=zh-Hans
```

工具先核对原 QA 包完整 game.json SHA，再用 validateSave 检查状态，保存为单场景 fixtures.json。若显式 entry 不同则拒绝；状态不手工改旗标，也不截断更多历史。**该副本是已有测试现场，不是玩家的真实存档**。原 QA 的历史可能只有 100 页；不能用它验收“完整历史保存”问题，也不能从它推定玩家走过某条路线。

指纹是版本识别，不是整个工作区/翻译/资源的冻结备份。报告中的源码 SHA 不证明 PNG 缓存已更新；媒体问题另记录具体资源 ID、路径、文件哈希与浏览器实际加载结果。修复后语言目录 SHA 改变是正常现象，复验记录同时注明前后基线。

## 复现、定位、修复

1. 核对候选句子和实际路线。需要连续上下文时使用 i18n:context；需要真实操作轨迹时使用 qa:replay。孤立源块不能伪装成从章节入口可达的路线。
2. 用独立测试窗口和存储。推荐启动专用端口，例如 `npm run dev -- --host 127.0.0.1 --port 5189 --strictPort`；测试页与正式游戏同 origin 时都会写自动存档。新标签页不隔离，多个无痕窗口也可能共享数据。
3. 先复现再改代码。记录初始页面、动作、异常及预期；视觉问题保留修复前截图。若不能复现，记录已经排除的环境和路线，保留“待复现”。
4. 区分源数据/解码、引擎、素材转换缓存、排版、浏览器、翻译、持久化。按 DEBUGGING 的证据顺序调查；不能看到黑屏就补背景、看到裁剪就全局 contain、看到错误就跳过指令。
5. 修复最小责任层。改指令语义需要原始处理器/偏移证据、最小回归及真实路线；翻译改动用工作台，不能直接改目录。改存档结构、脚本 PC 或 revision 前先说明旧存档迁移方案。
6. 用相同现场、动作、视口复验，并检查一个相邻正常场景。错误消失但剧情跳过、收录丢失、勇气不扣或存档不兼容，都不算修复完成。

## 按风险选择回归

| 改动 | 定向检查 | 实际操作与扩大范围 |
| --- | --- | --- |
| 文字、术语、高亮引用 | i18n:work check/apply；i18n:test；受影响章翻译门禁 | 正文、选项、历史、手帖/辞典、28px 长文；源语料变化再 extract |
| CSS、面板、按钮 | lint、check:qa、build | 桌面、360×740、440×956、844×390；真实点选/滚动/键盘，Safari 相关问题必须回 Safari |
| 背景、动画、媒体缓存 | check:game；scene.test / animation.test | 看实际时序与图层；检查原资源尺寸，定向重建缓存，不删除玩家数据 |
| 分支、勇气、推理、评分 | engine.test + 对应章完整测试；qa:replay --check-saves | 成功/失败/返回修改、相关相邻分支；不能仅跑缩短历史 UI 夹具 |
| 存档、刷新、语言路由 | engine.test / i18n.test + 受影响路线 | 保留旧存档副本；自动/手动、读回、刷新、语言及字号；确认异步写入成功 |
| 定位/报告工具、文档 | 对应工具测试、CLI 实跑、lint | 不改生产交互则无需重复全章人工游玩；报告输出不等于复现成功 |

用户要求完成一批游戏 bug 时，最终执行完整 `npm run verify`，记录实际结果；定向检查用于迭代提速，不能代替明确要求的全量验收。工具或纯文档维护按影响范围验证，并如实说明未重跑的项目。

## 关闭问题与交接

使用 docs/bugs/TEMPLATE.md。至少包括：玩家现象、确定的复现身份、根因证据、修改、修复前失败/修复后通过、实际浏览器范围、未覆盖边界。

状态：待复现 → 已复现 → 修复中 → 待验收 → 已验证。非 bug/暂缓也应记录依据。代码写完、截图数量、单元测试绿灯都不能单独把显示/交互问题标为已验证。同一根因可关联多个玩家反馈，但保留各自复验条件。

每批更新 PROJECT_STATUS 与 ACCEPTANCE；新增共性经验追加 DEBUGGING 或相应专题，避免把所有历史塞入“当前状态”。不自动把翻译 draft 升为 reviewed。
