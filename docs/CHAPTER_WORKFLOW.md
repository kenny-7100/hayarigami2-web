# 后续章节实施与验收流程

本流程把前几章的实际经验拆成可重复步骤。用户要求完整章节时，不能以“首页可进入”“跑通一条路径”或“无新 opcode”作为结束条件。

## 1. 建立边界与证据

先读 PROJECT_STATUS 和对应前章记录，运行 `npm run check:game`。记录当前 git 状态，保留既有未提交工作。原始镜像不是可编辑源代码。

```sh
npm run audit:chapter -- --catalog
npm run audit:chapter -- --chapter 2
npm run audit:chapter -- --script 30001
```

读输出 audit.json 的 scriptIds、opcodeSites、外部跳转和 baseline 差异；只打开相关 scripts.json 记录。按 EBOOT 注册表确认未知指令，按原始记录检查初始化、逻辑图调用、章节结束。**先确认章名、入口、范围和依赖，再写章节配置。** 没有生成反汇编时 unregisteredOpcodes 为 null，不能解释成空列表。

## 2. 文本与关系数据

- 检查正文、选项标签、关键词、辞典、推理说明是否使用相同编码。不能因为正文是日文就把关键词的汉化字节也按 CP932 解码。
- 先严格解码，出现异常定位原始字节/字形，添加有证据的特殊映射。禁止 errors=ignore、猜字或将替代字符当成功结果。
- 姓名控制码转 `{surname}` / `{givenName}`，保留正文片段拼接需要的空白；浏览器只见 Unicode。
- 确认 logic.dat 的记录、字段、开关标志、候选组、人物说明变体与纹理包。ID 2+chapter 和资源 22+logicId 目前只在已完成章验证，不可盲目外推。
- 未译文本原样保留。翻译是后续独立任务，不混入本章功能开发。

## 3. 控制语义与媒体补齐

扩展 compile_data 的明确允许范围，并将正文/关键词/关系图策略写成可审计配置；不要靠全局替换数字复制上一章。

每个首次出现的指令或新参数要形成“原始偏移 → native handler / 数据证据 → Web 行为 → 回归”的链路。已注册 native handler 不代表 Web 已实现；同 opcode 的新比较模式、带符号参数、变体也可能不支持。

资源收集必须扫描完整本章以及仍被依赖的序章记录，覆盖背景、立绘、音频、关系图和动画子资源。生成文件名避免不同章节/图号覆盖。先检查图层和动画再判断黑屏：既不能忽略缺资源，也不能把原版黑场补成背景。

合并 game.json 与 chapters/logics，加入首页入口、前章到本章的衔接、正确的结束显示。结束判定必须对应源逻辑；最终话还需要两条路线的持久完成标记，不能只加章节按钮。

## 4. 路线、错误路径与存档

建立可复现的科学/灵异（若实际存在）成功路线与错误推理路线。测试夹具应明确记录 `[script, pc, choiceIndex]`、正确答案、预期结尾和分数。下一章若不适用这两种路线，以真实分支结构为准。

通用 qa:replay 对已确认轨迹严格执行，缺选择或答案、位置漂移、提前结束、错误分数都失败。它不替你发现路线，不猜正确答案。单条路线停顿脚本集合不等于完整覆盖；仍需沿用现有 tests 中的固定种子分支巡检与每条指令执行覆盖方法。

必须检查：禁用/勇气不足选项、空关系栏、错误填答、确认后返回修改、失败结局、章节进入、姓名/历史/术语保留、每个停顿点完整历史 JSON 存档往返。快速浏览器检查点截取历史只用于 UI，不代替完整历史存档验证。

静态选择未执行时提供具体不可达证据，例如第一话 27220 在 instructions[72] 已无条件跳转，后方 [95] 不能从入口到达；不能用一张宽泛例外清单把覆盖缺口消掉。

## 5. 浏览器实际验收

启动正式入口及通用 QA 页，用独立测试存储。至少检查：

| 类别 | 必查内容 |
| --- | --- |
| 图片 | 原生背景/长图运镜/负尺寸/立绘/真正黑场/动画整幅场景/思考条幅 |
| 操作 | 逐段继续、选择、输入、关系图与人物说明、提交与返回修改 |
| 持久化 | 自动存档、手动保存/读取、刷新继续、字号/音量 |
| 面板 | 长历史与加载更多、长辞典、关闭按钮、提示在模态框内可见 |
| 布局 | 桌面、360×740、440×956、844×390；大字号、长文本、长选项 |
| 媒体 | 点击开启声音、循环/单次、普通翻页动画不重启、换场景与读档 |
| 可达性 | 键盘焦点、方向键/回车/空格、移动滚动、底部按钮可达 |

先走真实剧情，再用检查点复现边界。浏览器无报错和截图正确都不足以单独证明交互成功；实际点选、保存、读回并观察后续状态。

## 6. 交付门槛

- 编译所有确认范围内的记录，资源引用无缺项；没有无依据的 skip/no-op 或占位图。
- 成功/失败路径及分支覆盖达标；明确不可达例外与未穷举组合。
- `npm run verify` 全部通过；必要时完整 prepare:game 验证可重建。
- 实际浏览器验收通过，未验证的设备/逐帧效果明确写出。
- 更新章节文档、PROJECT_STATUS、ACCEPTANCE 和新增逆向证据；把尚未解决的风险写清，不用“下一步可以”替代本次必要工作。
